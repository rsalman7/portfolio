What came out of it

Separating geometry, trajectory planning, and communication made it possible to inspect a planned move before sending it to the robot. Hardware testing then guided changes to the motion settings and timing.

Inside the motion controller

Define the working plane

Three calibration points establish an origin and two perpendicular axes. The code uses that frame to map local drawing coordinates into Cartesian positions while retaining a reference tool orientation.

Shape each move

A seven-phase S-curve controls how each straight segment accelerates and decelerates. The planner is configured to sample positions every 8 ms and bring each segment to rest at its endpoint.

Exchange commands and feedback

The UDP client receives a robot-status packet, checks the ready flag, and sends the next position using the returned sequence number. Packet encoding and response parsing sit in a separate protocol module.

Code: calibrated coordinates

Map a drawing point into 3D

This transform maps a point on the calibrated plane into the robot’s coordinate system. The origin and unit axes are established from the three calibration points.

def to_global(self, u: float, v: float) -> np.ndarray:
    return self.origin + u * self.u_axis + v * self.v_axis

Project a 3D point back onto the plane

In geometry.py, to_local subtracts the plane’s origin and takes dot products with its two unit axes to recover local coordinates.

def to_local(self, point: np.ndarray) -> Tuple[float, float]:
    """Project a 3D point onto the plane, returning (u, v) coordinates."""
    delta = np.asarray(point[:3]) - self.origin
    u = float(np.dot(delta, self.u_axis))
    v = float(np.dot(delta, self.v_axis))
    return (u, v)
Code: S-curve motion planning

Find a peak velocity that fits the move

For a short move, the requested top speed may leave too little distance to accelerate and decelerate. This routine in trajectory.py searches for a feasible peak velocity using the available distance and the acceleration and jerk limits.

def _find_max_velocity(self, d: float, a: float, j: float) -> float:
    """Binary search for the max velocity that fits in distance d."""
    v_lo, v_hi = 0.0, self.v_max
    for _ in range(64):  # plenty of iterations for convergence
        v_mid = 0.5 * (v_lo + v_hi)
        s = self._accel_distance(v_mid, a, j)
        if 2 * s <= d:
            v_lo = v_mid
        else:
            v_hi = v_mid
    return 0.5 * (v_lo + v_hi)

Turn the profile into sampled poses

After the profile and segment endpoints are defined, generate_segment_points converts each sampled distance into a fraction of the move. It clamps that fraction to the segment bounds and interpolates the pose.

Code: robot feedback and offline checks

Decode the packet header and status flags

In protocol.py, parse_response reads the header fields in big-endian byte order. Bit masks turn the status byte into named flags for readiness, command acceptance, command receipt, and motion.

# Header
state.packet_type = struct.unpack(">I", data[0:4])[0]
state.version = struct.unpack(">I", data[4:8])[0]
state.seq_no = struct.unpack(">I", data[8:12])[0]

# Status bits
status_byte = struct.unpack(">B", data[12:13])[0]
state.status = RobotStatus(
    sysrdy=(status_byte & 0b0001) > 0,
    accept_cmd=(status_byte & 0b0010) > 0,
    received_cmd=(status_byte & 0b0100) > 0,
    in_motion=(status_byte & 0b1000) > 0,

From raw logs to CSV

The parser extracts timestamps, temperature, pressure, two A-channel values, UV readings, and four raw and four converted EFM values into 14 columns.

It trims whitespace, retains missing readings recorded as None, and skips lines that do not match the expected log pattern. The result is a CSV that opens in Excel.
